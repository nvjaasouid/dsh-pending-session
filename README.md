# dsh-pending-session
**把还没发送的会话草稿 保存在侧边栏**

[English](README.en.md) | 中文

![待执行 示例](docs/pending-row.png)

## 核心功能
在一个会话里输入了内容但还没发送时 进入其他会话或开启新会话,原新会话不再被隐藏 而是作为一个条目留在侧边栏里 与其他对话记录并列,显示名称为'待执行'

待执行可同时存在多个
待执行与正常会话之间,每个待执行之间互不影响

待执行与其他正常会话一同按最近一次向dsh发送对话的时间排序
· 待执行的时间是它创建的时间 —— 只是编辑草稿,不会改变它的时间和位置

只有「有草稿(文字或附件)的空白会话」会留下,已经发过消息的对话不受影响
草稿和附件都存在本地,关掉再打开还在

## 待执行能怎么交互
可以随时:
    更改内容 —— 点进去就是原来的输入框,文字和附件原样还在,接着写
    重命名 —— 行菜单里的「重命名」,或者双击标题
    归档 —— 从侧边栏收起,但**不是删除**,在「归档会话」里还能找回来
    删除 —— **真删除,不可恢复**;正在运行的会话不允许删除
    发送 —— 发送后它就不再是待执行,变成一条普通对话,并按发送时间排到最上面

## 安装 / 卸载

**安装**（任选一种）：

```sh
# 1) 在 dsh 的插件管理器里（设置 → 插件）按名字安装
dsh-pending-session
```

```sh
# 2) 在 profile 目录下用包管理器装
pnpm add dsh-pending-session
```

> [!IMPORTANT]
> 装完请**重启一次 dsh** —— 插件的宿主半边在启动时加载，不重启的话删除功能不生效。

**卸载**：

```sh
# 在插件管理器里禁用 / 移除，或者：
pnpm remove dsh-pending-session
```

已有对话、归档记录都不受影响，侧边栏恢复成原生样子。

## 安全与数据

> [!CAUTION]
> ### ⚠️ 删除 = 真删除，**不可恢复**
> 这个插件会在每条会话行的「…」菜单里加一项「删除会话」。
> 它会清掉**会话日志、投影缓存、工作区记账** —— 不是归档，找不回来。

- 🚫 **正在运行的会话（agent 还在输出）不允许删除**
- 📦 **归档 ≠ 删除**：归档只是从侧边栏收起，在「归档会话」里还能找回来
- 🧹 草稿清空到只剩空白后离开，条目会被自动收走（仅归档，不删数据）
- 🛡️ 删除由插件自带的宿主端点完成；该端点不可用时，退回系统原生的归档行为

## 原理（为什么这么设计）
1. **只对空白会话生效**：dsh 的「新会话」本身就是空白会话，草稿只存在输入框里；已经发过消息的对话有自己的记录，插件不去碰
2. **条目是投影出来的**：插件把保存的草稿会话投影成侧边栏里的一条普通记录（非空白行），所以它能和正常对话并列、一起排序、一起被归档过滤
3. **删除自己实现**：dsh 原生只有归档，而第三方删除插件会拒绝删除「宿主进程仍持有」的会话；本插件自带宿主端点直接清理存储与记账，并在界面里立刻隐藏该行
4. **全程只读**：插件不会 retain/using 去触碰会话 —— 那会把会话钉在宿主内存里，反而更删不掉
